The Android instrumentation APK builds locally; the new native cases run in the
normal GitHub Android 11/API 30 job alongside the eight existing native tests.
Final-head results and captured native pages are linked on the PR after CI completes.
No paid model test or university credential is required for this feature.

The initial native runs passed 10 of 11 cases, including the renderer and encrypted
storage tests. The reader workflow exposed a test-input error: `pinch` takes
`start0, end0, start1, end1`, while the original call grouped starts then ends.
That translated both fingers instead of increasing their separation. Named
arguments now express the actual pinch; the host flow also checks zooming from
fit-page scale and requires a material increase, rather than floating-point drift.
Coordinates avoid the centered note's touch target and the canvas scrolls into view.
A single shell script collects screenshots even after failed instrumentation and
preserves its exit status; the emulator action executes multiline entries as
separate shells. See the PR's final-head report for the complete native result.

## Host rendering boundary

The 25 host captures below use the production Compose screens and ViewModel with
an authored three-page PDF. Their university adapter throws on every operation
except reading the already saved snapshot. Account/session writes are forbidden.
Local persistence is an isolated test adapter; real encryption is tested separately
on Android.

Robolectric SDK 35 native graphics can draw Compose but cannot construct this
platform PdfRenderer on the host JDK: it raises
`NoSuchMethodError: java.io.FileDescriptor.getOwnerId$()`. Do not call a passing host
screenshot a native PDF-engine test. The host renderer adapter uses pages
independently rendered with PyMuPDF from the exact authored PDF, checks its SHA-256
against the Kotlin fixture and displays those pages in the real production reader.
Native Android instrumentation uses the actual production PdfRenderer instead.

The [PDF fixture](design/fixtures/reading-synthetic.pdf) is generated by
`ReadingFixtures` (three vector pages, Helvetica, graph-traversal material). It is
explicitly synthetic and contains no downloaded university document, personal
profile, credentials or student note. The encrypted-PDF fixture is also authored
synthetic material, with fixture-only passwords. All displayed notes are authored
fixtures. No real UIT source or credential is published in the gallery or CI.

## Reproduce

```sh
JAVA_HOME=/tmp/uit-jdk ./gradlew :core:domain:exportReadingFixture
JAVA_HOME=/tmp/uit-jdk ./gradlew :app:testDebugUnitTest \
  --tests '*Reading*Test' --tests '*WidgetNavigationTest.reading*' -PrecordUi=true
JAVA_HOME=/tmp/uit-jdk ./gradlew :app:assembleDebug :app:assembleDebugAndroidTest check
```

Regenerate `app/src/test/resources/reading/page-{1,2,3}.png` from the exported PDF
with PyMuPDF at 2×, then copy the exported SHA-256 into `document.sha256`. These are
review/test fixtures, not a runtime app dependency. Actual Android PDF validation
requires an Android device/emulator; follow [rootless SSH debugging](DEBUGGING.md).

The current implementation uses page-linked text/pin annotations and JSON sidecar
export. It does not claim freehand/highlight editing inside PDF bytes, sidecar
import, OCR, PDF text selection or a semantic accessibility tree for page bodies.
