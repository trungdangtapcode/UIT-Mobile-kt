# Interface language (English/Vietnamese)

The app ships two interface languages. Vietnamese is the default; a student can
switch to English in **Account icon → Settings → Language**.

## Policy

* Source identifiers, comments, documentation and tooling output stay English.
  Vietnamese appears only in `values-vi/` resources and in text copied from UIT
  portals.
* English remains the resource default (`values/`). Vietnamese translations live
  in `values-vi/`, so a missing translation falls back to English instead of
  crashing.
* The selected language is stored in the existing `appearance` preferences under
  the `language` key (`vi` or `en`). `LanguagePreference` in
  `core:designsystem` reads it; `withAppLanguage` wraps a context for surfaces
  that cannot use Compose (widgets, notifications).
* Portal data is never translated: course names, notices, profile values and
  DAA announcements keep the wording supplied by the university. Parser patterns,
  regular expressions, CSS selectors and API paths are not translated either.
* Input formats stay locale independent. Date fields keep `YYYY-MM-DD` and time
  fields keep `HH:mm`; the parsers depend on those exact shapes.
* Numbers: GPA and scores always use a dot (`Locale.US`), tuition amounts keep
  the Vietnamese grouping and the `₫` suffix in both languages.
* Dates and weekdays use `mediumDate`, `monthYear`, `shortWeekday` and
  `longWeekday` from `core:designsystem/DateFormat.kt`, which format with the
  selected language rather than the device locale.

## Resource layout

| Module | Purpose |
| --- | --- |
| `core:designsystem/res/values(-vi)` | Shared components, navigation labels, schedule kinds, due-time wording and date patterns |
| `core:data/res/values(-vi)` | Background notification channel and titles |
| `feature:*/res/values(-vi)` | Screen-specific text |
| `app/res/values(-vi)` | Widget rendering and widget picker |
| `core:auth/res/values(-vi)` | Existing SSO browser dialog strings |

Key names follow `<screen>_<section>_<role>`, for example
`courses_upload_confirm_title` or `acad_semester_performance`. Shared keys use
the `common_` prefix where they exist. Every key added to `values/` must be added
to `values-vi/` in the same change; Android lint reports `MissingTranslation` as
an error, so a partial translation fails the build.

## Adding or changing text

1. Add the English string to the owning module's `values/`.
2. Add the Vietnamese translation to the same module's `values-vi/`.
3. Replace the literal with `stringResource(R.string.key)`. Use
   `pluralStringResource` for counts and keep format arguments typed (`%1$s`
   for text, `%1$d` for integers).
4. Run `./gradlew -Pheadless formatKotlin`, then `:app:assembleDebug` and the
   module's unit tests.
5. Run `python3 scripts/check-hardcoded-ui-strings.py`. It fails when a
   `Text("literal")` remains in production sources; data templates
   (`"${...}"`), internal filter identifiers and capitalised codes are ignored.

## Surfaces outside Compose

* **Widgets** render through `RemoteViews`, so the renderer resolves text with
  `localized.getString(...)` using the saved preference. The launcher does not
  read the app language for us.
* **Notifications** are built in `UitSyncWorker`, which creates a localized
  configuration context before reading its resource strings. The channel id
  `uit_updates` never changes; the channel name is fixed when it is first
  created, so devices that already had the channel keep the old name until the
  app data is cleared.
* **Activity language** is applied in `MainActivity.attachBaseContext`, so
  Compose resources, dialogs and window text all resolve the same language.
  Changing the setting recreates the activity; ViewModels survive the
  configuration change.

## Review workflow

1. Translate only after the English copy is final for that screen.
2. Keep terminology aligned with the university: Lớp học phần, Tiết, Ca thi,
   Học bù, Nghỉ học, Hạn nộp, Tín chỉ tích luỹ, Học phí, Còn phải nộp, Thủ tục,
   Tốt nghiệp, Tải ngoại tuyến, Thời gian rảnh, Danh mục kiểm tra.
3. Review the Vietnamese build on a 360dp phone with 1.3× font scale; Vietnamese
   text is 20–35% longer than English and is the most common source of clipping.
4. A passing build or test suite is not visual approval. Review the rendered
   screen itself.

## Limits

* Device language is ignored on purpose: the app default is Vietnamese.
* The widget uses the app preference, but launchers keep their own text scaling;
  a very large system font can still reduce visible rows.
* Portal-provided values can appear in either language because the university
  supplies them; that is not a translation defect.
